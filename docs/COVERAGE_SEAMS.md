# Coverage seams

The 2026-10-20 audit reviewed 49 `TODO(coverage)` markers: 27 internal invariant cases were removed, and the remaining 22 cases now have implemented boundaries and deterministic tests. No coverage markers remain for this inventory. The original invariant findings are retained below.

The seams follow existing responsibilities. `ProjectRoot` owns the lossless representation of a canonical workspace directory; `SearchGenerations` represents which query may still publish. Cache codecs, durable files, catalog storage, filesystem discovery, transport streams, and worker acquisition are infrastructure boundaries. They do not introduce a test mode, configurable fault flags, arbitrary checkpoints, or a second production algorithm. Test doubles live in test modules.

## Cache I/O

[cache.rs](../native/context-index/src/cache.rs) separates the version-one byte format (`encode` / `decode`) from cache publication. `PendingCacheFile` exposes its writable stream and its separate synchronization barrier. The production adapter remains a `File` with a `BufWriter<&File>`; the factory still creates an exclusive temporary file with mode `0600` on Unix.

Publication retains its exact sequence: encode, flush, drop the writer, synchronize the file, replace the destination. Any failure after file creation still removes the temporary file. There are no new retries or changes to replacement behavior.

| Original marker                | Implemented test in [cache/tests.rs](../native/context-index/src/cache/tests.rs)                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Final trailing-byte read fails | `decoding_reports_an_io_fault_after_a_complete_record` supplies a valid record followed by a read error and checks the original diagnostic. |
| Header write fails             | `failed_cache_publications_preserve_the_previous_file_and_remove_the_temporary` fails the header through the pending-file writer.           |
| Metadata write fails           | The same test fails after the magic, policy hash, and root bytes have been accepted.                                                        |
| Flush fails                    | The same test accepts serialization but rejects flush; sync must not run.                                                                   |
| Synchronization fails          | The same test accepts flushing but rejects sync; installation must not run.                                                                 |

Each publication-failure case verifies the exact diagnostic, operation ordering, unchanged previous cache, and absence of temporary files. `cache_encoding_preserves_the_version_one_wire_format` checks the encoded bytes against the existing format. Existing filesystem round-trip and replacement tests still exercise the concrete adapter.

## Search scheduling

[content_search.rs](../native/context-index/src/content_search.rs) now separates three responsibilities: reading searchable files, producing one ordered lane of file results, and collecting lanes in catalog order. `SearchableFiles` is the workspace content source; its production implementation calls the existing guarded file reader. Editor overrides retain precedence and their existing size/NUL checks.

`search_lane` owns cancellation and bounded sending. `collect_outcomes` owns ordered reduction, page completion, and receiver lifetime. Production still uses the same worker count, one capacity-one channel per lane, the same atomic memory orderings, and the same cancellation checks. Receivers are dropped before the scoped workers join.

| Original marker                                 | Implemented test in [content_search/tests.rs](../native/context-index/src/content_search/tests.rs)                                                                                     |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Worker observes cancellation or page completion | `lanes_stop_after_cancellation_or_page_completion_without_reading_another_file` changes each flag after the first file and verifies that the second file is never read.                |
| Send fails after consumer closure               | `closing_the_consumer_ends_a_lane_after_its_in_flight_file` closes the real receiver during a file operation and verifies that no subsequent file is read.                             |
| Receive fails after a worker exits              | `a_cancelled_lane_closes_the_channel_before_the_collector_receives_a_result` uses an actual cancelled lane and disconnected channel; collection terminates without inventing a result. |
| Cancellation arrives after search admission     | `cancellation_during_file_io_returns_cancellation_instead_of_partial_success` cancels during a real guarded file read and checks the search-level error.                               |

`a_page_is_reduced_in_catalog_order_and_releases_all_lanes` additionally queues results out of order, verifies the first page, and checks that every sender observes closure.

The fifth scheduling marker, in [index.rs](../native/context-index/src/index.rs), uses `SearchGenerations`. The production implementation reads the same `AtomicU64` with acquire ordering. `a_generation_superseded_during_matching_does_not_publish_and_can_be_retried` in [index/tests.rs](../native/context-index/src/index/tests.rs) advances the authority between admission and the post-tick check, verifies `Superseded`, and then retries the same query successfully. No matcher callback or artificial scheduler checkpoint is needed.

## Monitor startup

[workers.rs](../native/context-index/src/workers.rs) provides `WorkerFactory`, an acquisition port returning real `JoinHandle`s. `SystemWorkers` preserves the three existing named thread roles and leaves content-search threads unnamed. It does not catch panics, retry startup, or introduce an executor. Named-thread startup still returns errors; content-search startup retains the existing panic-on-spawn-failure policy.

[service.rs](../native/context-index/src/service.rs) composes initialization with that factory. Watcher construction has a separate factory because watcher registration and thread acquisition are different resources.

| Original marker                                   | Implemented test in [service/tests.rs](../native/context-index/src/service/tests.rs)                                                                                              |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Monitor spawn error is mapped                     | `monitor_startup_failure_does_not_publish_initialized_state_and_allows_retry` injects the OS-style spawn error and verifies its existing diagnostic.                              |
| Initialization propagates monitor startup failure | The same test verifies that no initialized state or monitor handle is published, then retries with the production factory successfully.                                           |
| Watcher construction fails                        | `watcher_construction_failure_uses_the_existing_unwatched_monitor_path` injects the backend factory error and verifies that the unwatched monitor still reconciles the directory. |

The existing debounce, startup-delay, watcher-disconnection, and periodic-reconciliation tests remain in place. Worker adapter tests check actual thread names and joined return values.

## Reconcile scheduling

`CatalogRepository` in [service.rs](../native/context-index/src/service.rs) provides an authoritative path snapshot and its optional cache checkpoint. `FilesystemCatalog` delegates to the existing scanner and cache store. The service retains ownership of publishing the new index, known paths, and truncation state, including the original independent lock operations.

| Original marker                    | Implemented test in [service/tests.rs](../native/context-index/src/service/tests.rs)                                                                                                                |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shutdown after successful scanning | `shutdown_during_catalog_io_does_not_publish_the_new_snapshot` stops during the scan operation. It verifies that neither a checkpoint nor new shared state is published.                            |
| Shutdown after cache storage       | The same test stops after writing a real checkpoint. The cache contains the new snapshot, while the live index, known paths, and truncation state remain unchanged, matching the existing behavior. |

The checks remain at their existing boundaries. Cache errors remain advisory, and the repository does not combine checkpointing and live publication into a new transaction.

## Worker panics

`serve` in [protocol.rs](../native/context-index/src/protocol.rs) owns transport streams and worker lifetimes. The standard-I/O composition opens the same streams on the same threads and at the same points as before. The service owns its content-search worker handles. Both use `WorkerFactory`; only tests substitute failing or panicking tasks.

| Original marker                         | Implemented test in [protocol/tests.rs](../native/context-index/src/protocol/tests.rs)                                                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Service worker join fails               | `transport_reports_worker_startup_and_join_failures_without_changing_error_precedence` checks the service panic diagnostic.                                                               |
| Writer join fails                       | The same test checks the writer panic diagnostic after a successful service completion. It also checks both named-worker startup errors.                                                  |
| Finished content-search worker panicked | `a_finished_panicked_search_is_reported_before_the_next_request_is_executed` returns a real, already-finished handle and verifies that the next request does not execute.                 |
| Shutdown joins a panicked search        | `shutdown_and_input_eof_cancel_and_join_pending_panicked_searches` holds the worker until the registry is cancelled by shutdown, then panics. No successful shutdown response is emitted. |
| Input EOF joins a panicked search       | The same test closes the request channel and holds the worker until the EOF drain cancels it. The failure is verified at that final join.                                                 |

The tests synchronize on worker completion or the service's cancellation flag rather than hoping to hit a timing window. Bounded waits are failure guards. Production still propagates the same errors with the same precedence and cleanup behavior; this change does not attempt to redesign failure recovery.

## Validation

Validated on macOS after implementation:

- `cargo test --workspace --quiet`: 167 tests passed; five existing benchmark or host-specific cases were ignored. The added Linux-only symlink case is not compiled on macOS.
- `cargo clippy --workspace --all-targets -- -D warnings`: passed.
- `cargo build --release --package glyph-context-index`, followed by `pnpm exec vitest run --project e2e --maxWorkers=2 src/context/search/tests/RustWorkspacePathIndex.e2e.test.ts`: both tests against the real process passed.
- An isolated `cargo llvm-cov --workspace --json -- --skip measures_` run exercised all 22 former marked paths, including the error-producing closures and early returns. This is scoped evidence for this inventory, not a claim of 100% repository coverage.
